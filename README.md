# noxis

Обфускатор JVM/Java-байткода на Rust.

Читает JAR, переписывает классовые файлы и ресурсы, собирает обратно —
детерминированно, с маппингами для stack trace и с проверкой, что выход
действительно загружается настоящей JVM.

## Структура

```text
noxis/
├── Cargo.toml              workspace, lints, release-профиль
├── scripts/check.sh        structure → fmt → clippy → test
├── docs/                   ← архитектура, техники, стек, уроки
├── info/                   исходный материал разбора (вне правил)
└── crates/
    ├── noxis-classfile/   IR + парсер/запись + StackMapTable
    ├── noxis-core/        конфиг, seed, маппинги, контракт Pass
    ├── noxis-analysis/    иерархия, entrypoint'ы, keep
    ├── noxis-passes/      сами трансформации + конвейер
    ├── noxis-runtime/     схемы шифрования, ABI декодера
    ├── noxis-jar/         ZIP, ресурсы, срез подписей
    ├── noxis-verify/      red-паттерны, java -Xverify     (план)
    ├── noxis/             CLI                             (план)
    └── noxis-structure-check/  автогейт структуры
```

## Быстрый старт

```sh
./scripts/check.sh     # fmt + clippy -D warnings + тесты
```

Одно `cargo build` уже гоняет проверку структуры проекта: если файл
длиннее 250 строк или в директории больше 4 файлов, сборка падает.
Правила — в [`docs/README.md`](docs/README.md).

## Принципы

- **KISS / DRY / SOLID.** Файл — одна ответственность. Не больше 250 строк,
  не больше 4 файлов в директории.
- **Детерминированность.** Один seed → байт-в-байт одинаковый артефакт.
- **Ничего не ломаем.** Техника, которая может дать `VerifyError`,
  включается только после верификатора.
- **Измеримо.** Защита без метрик — это мнение, а не свойство.

## Ответственное использование

`noxis` — инструмент двойного назначения. Он одинаково полезен для
защиты собственного байткода и способен усложнять анализ вредоносного
ПО. Лицензия это не регламентирует, но это норма сообщества проекта:

- используйте обфускацию, чтобы защищать **свой** код и код тех, кто
  вас об этом попросил;
- не применяйте инструмент для упаковки вредоносов, обхода средств
  защиты и антивирусов или иной деятельности, запрещённой законом.

Нарушение этих норм не влечёт юридических последствий по лицензии, но
приведёт к отказу в поддержке и закрытию issue/PR в репозитории.
